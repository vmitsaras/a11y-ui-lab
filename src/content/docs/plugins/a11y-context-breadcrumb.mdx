`a11y-context-breadcrumb` progressively enhances a semantic navigation landmark with an ordered breadcrumb generated from headings in a specified content region. As a reader scrolls, it renders the active heading hierarchy, marks the current crumb with `aria-current`, and can announce concise section changes. It does not initialize on import or replace the underlying article.

<Aside type="note" title="Contextual, not site-wide navigation">
  This package derives local context from headings in the current document. It does not create global site breadcrumbs, a table of contents, router state, or information architecture. Keep those concerns in the application.
</Aside>

## Use when

- A long, nested guide or policy has meaningful heading structure and benefits from a compact current-location indicator.
- Readers may enter a document at a deep anchor and need a visible path through its section hierarchy.
- Heading IDs can serve as stable in-page destinations, or the integration can provide a safe `getHref()` callback.
- The existing page remains usable as a normal document when JavaScript is unavailable.

## Avoid when

- A conventional site breadcrumb based on URL hierarchy is needed; this package reads document headings instead.
- The page’s headings are presentational, inconsistent, frequently reordered without `refresh()`, or lack a meaningful hierarchy.
- A table of contents, tabs, stepper, disclosure pattern, or a general-purpose scrollspy is the actual interaction need.
- The application cannot ensure that heading labels and destinations are safe, understandable, and stable.

Import the root ESM entry and its public CSS export. Importing alone does not inspect or change the page.

```js
import { createA11yContextBreadcrumb } from 'a11y-context-breadcrumb';
import 'a11y-context-breadcrumb/styles.css';

const root = document.querySelector('[data-a11y-context-breadcrumb]');

if (root instanceof HTMLElement) {
  createA11yContextBreadcrumb(root, {
    contentRoot: '#article',
    baseLabel: 'Guides',
    baseHref: '/guides/',
  });
}
```

Use `initA11yContextBreadcrumbAll(options?)` when a document deliberately contains more than one root. It initializes every `[data-a11y-context-breadcrumb]` element in document order.

## Required markup

Author a real navigation landmark, an ordered list, and a content region with a meaningful heading structure. The root can use a non-`nav` element, but the package only adds `role="navigation"` when no role exists; a `<nav>` is clearer in authored HTML.

```html
<nav
  class="a11y-context-breadcrumb"
  aria-label="Current section"
  data-a11y-context-breadcrumb
  data-a11y-context-breadcrumb-content-root="#article"
>
  <ol class="a11y-context-breadcrumb__list" data-a11y-context-breadcrumb-list>
    <li class="a11y-context-breadcrumb__item">
      <span class="a11y-context-breadcrumb__text">Guides</span>
    </li>
  </ol>
</nav>

<main id="article" data-a11y-context-breadcrumb-content>
  <h2>Forms</h2>
  <section data-a11y-context-breadcrumb-label="Errors">
    <h3>Error summary patterns</h3>
  </section>
  <aside data-a11y-context-breadcrumb-skip>
    <h3>Related internal note</h3>
  </aside>
</main>
```

The public selectors are `[data-a11y-context-breadcrumb]`, `[data-a11y-context-breadcrumb-list]`, `[data-a11y-context-breadcrumb-content]`, `[data-a11y-context-breadcrumb-label]`, and `[data-a11y-context-breadcrumb-skip]`. The package creates a list when the list selector is missing. A label attribute on a heading—or on a container whose first matching heading it contains—supplies a shorter breadcrumb label. The skip attribute excludes an entire subtree.

By default, the package reads `h2, h3, h4` in `main`; prefer an explicit `contentRoot` for predictable scope. Missing heading IDs are generated by default for fragment links and removed only if this instance generated them during `destroy()`.

## Options and data attributes

JavaScript options override the matching root data attributes. String dataset booleans must be exactly `"true"` or `"false"`; non-negative integer options accept parseable non-negative integers, otherwise their defaults apply. Callback and `baseItems` options are JavaScript-only.

| Option | Data attribute | Default | Purpose |
| --- | --- | --- | --- |
| `contentRoot` | `data-a11y-context-breadcrumb-content-root` or marker value | `"main"` | CSS selector or `HTMLElement` containing headings. |
| `headingSelector` | `data-a11y-context-breadcrumb-heading-selector` | `"h2, h3, h4"` | Heading selector to read. |
| `baseLabel` / `baseHref` | `…-base-label` / `…-base-href` | `""` / `""` | Optional first breadcrumb item. |
| `baseItems` | — | `[]` | Explicit `{ label, href }` leading items; takes precedence when non-empty. |
| `maxItems` | `…-max-items` | `4` | Maximum displayed items; middle parents collapse when it is at least 3. |
| `collapseLabel` / `collapsedAriaLabel` | `…-collapse-label` / `…-collapsed-aria-label` | `"…"` / `"Collapsed parent sections"` | Visible and accessible collapsed-item text. |
| `separator` | `…-separator` | `"/"` | Visual separator; it is hidden from assistive technologies. |
| `sticky` / `topOffset` / `activeOffset` | `…-sticky` / `…-top-offset` / `…-active-offset` | `true` / `16` / `112` | Sticky layout, its pixel offset, and active-heading viewport offset. |
| `generateIds` | `…-generate-ids` | `true` | Generate missing heading IDs for default fragment links. |
| `linkItems` / `linkCurrent` | `…-link-items` / `…-link-current` | `true` / `false` | Render eligible items as anchors and optionally link the current item. |
| `announceChanges` | `…-announce-changes` | `true` | Add a polite, visually hidden active-section status. |
| `includeHiddenHeadings` | `…-include-hidden-headings` | `false` | Include headings hidden, inert, `aria-hidden`, `display:none`, or hidden by visibility. |
| `currentValue` | `…-current-value` | `"location"` | Value for `aria-current` on the current crumb. |
| `getLabel` / `getHref` / `shouldInclude` | — | `null` | Override a heading label/href or filter a heading. |
| `renderItem` | — | `null` | Return a custom node for an item, with `createDefault()` available in context. |
| `onChange` | — | `null` | Receive active-path changes after the package updates. |

Replace the `…` prefix with `data-a11y-context-breadcrumb`; for example, `data-a11y-context-breadcrumb-max-items="5"`. Invalid content-root or heading selectors do not throw through the public API: the package falls back to a content candidate where possible or dispatches an error event for an invalid heading selector.

## Runtime API and methods

| Export or method | Purpose |
| --- | --- |
| `createA11yContextBreadcrumb(root, options?)` | Enhance one root; repeated calls for the same root return the existing instance. |
| `initA11yContextBreadcrumbAll(options?)` | Enhance all matching roots. |
| `A11yContextBreadcrumb` | Public class for direct construction and advanced TypeScript integrations. |
| `refresh()` | Re-resolve the content root, re-read headings, rebuild paths, and force a current-state update. Call after application-owned heading changes. |
| `update(reason?, force?)` | Recalculate the active path from viewport positions; `force` renders even when the path signature is unchanged. |
| `destroy()` | Remove window listeners, package-created status/list/state, generated IDs, and package-added role or label; restore an authored list’s initial HTML. |
| `A11yContextBreadcrumbDefaults` | Frozen normalized defaults. |
| `A11yContextBreadcrumbSelectors` | Frozen public root, list, content, label, and skip selectors. |
| `A11yContextBreadcrumbEvents` | Frozen event-name constants. |

Instances expose `root`, normalized `options`, `contentRoot`, `headingItems`, `activeItem`, and `activePath` as public runtime properties. Their declarations also export the options, base-item, path-item, change-context, render-context, and instance types.

## Events

Events are synchronous bubbling `CustomEvent`s dispatched from the breadcrumb root. They are not cancelable; the published runtime does not set `composed`, so treat them as contained by a Shadow DOM boundary. Every event detail includes `instance`.

| Event | When | Additional detail |
| --- | --- | --- |
| `a11y-context-breadcrumb:init` | Initial setup completes. | `contentRoot`, `headings` |
| `a11y-context-breadcrumb:refresh` | `refresh()` finishes. | `contentRoot`, `headings` |
| `a11y-context-breadcrumb:change` | The active path changes, or an update is forced. | `reason`, `activeItem`, `path` |
| `a11y-context-breadcrumb:render` | A path is rendered. | `path`, `displayPath`, `activeItem`, `list`, `items` |
| `a11y-context-breadcrumb:error` | A content root is absent or the heading selector is invalid. | `message`; invalid-selector errors also include `selector` |
| `a11y-context-breadcrumb:destroy` | Cleanup completes. | No additional documented fields. |

On normal construction, `refresh()` and its forced `change`/`render` occur before `init`. Attach DOM listeners before calling the factory if that initial lifecycle matters. `onChange` is an option callback, invoked after an effective change event.

Version 1.0.0 publishes no addon, adapter, theme, or alternate-runtime subpath exports. Use the root runtime, `a11y-context-breadcrumb/docs`, and `a11y-context-breadcrumb/styles.css` only. ## CSS and customization

The public stylesheet provides the ordered-list layout, sticky positioning, horizontal overflow handling, current-item treatment, a visible link focus outline, responsive font sizing, and reduced-motion scroll behavior. Import it from the public CSS export, then set public custom properties on the root.

```css
.article-breadcrumb {
  --a11y-context-breadcrumb-bg: #ffffff;
  --a11y-context-breadcrumb-color: #172033;
  --a11y-context-breadcrumb-muted: #475569;
  --a11y-context-breadcrumb-border: #0e7490;
  --a11y-context-breadcrumb-radius: 0.5rem;
  --a11y-context-breadcrumb-shadow: 0 0.5rem 1.5rem rgb(15 23 42 / 0.16);
  --a11y-context-breadcrumb-gap: 0.5rem;
  --a11y-context-breadcrumb-z: 20;
  --a11y-context-breadcrumb-top: 1rem;
  --a11y-context-breadcrumb-font-size: 0.875rem;
  --a11y-context-breadcrumb-font-size-small: 0.8125rem;
}
```

Public hooks include `.a11y-context-breadcrumb`, `.a11y-context-breadcrumb__list`, `.a11y-context-breadcrumb__item`, `.a11y-context-breadcrumb__item--current`, `.a11y-context-breadcrumb__item--collapsed`, `.a11y-context-breadcrumb__link`, `.a11y-context-breadcrumb__text`, `.a11y-context-breadcrumb__separator`, `.a11y-context-breadcrumb__ellipsis`, `.a11y-context-breadcrumb__status`, `.a11y-context-breadcrumb__visually-hidden`, plus `.is-initialized` and `.is-sticky`. Keep a clear `:focus-visible` indicator, preserve the text alternative for collapsed items, and do not rely on the stylesheet’s private `--_a11y-context-breadcrumb-*` variables.

## Keyboard interaction and focus

| Key | Context | Behavior |
| --- | --- | --- |
| <kbd>Tab</kbd> / <kbd>Shift</kbd>+<kbd>Tab</kbd> | Page | Move through rendered breadcrumb links in normal document order. Non-linked and collapsed items add no tab stop. |
| <kbd>Enter</kbd> | Focused breadcrumb link | Follows the native anchor destination when that item is linked. |
| Native browser link shortcuts | Focused breadcrumb link | Remain browser and platform owned. |

The package does not implement arrow-key roving focus, focus trapping, or a custom keyboard model. It never moves focus during initialization, scroll updates, `refresh()`, or `destroy()`. Before replacing its list, it records the focused breadcrumb link’s `href` and focuses the replacement link with the same href when present, using `preventScroll`; if the corresponding link is gone, it does not choose a new focus target. Fragment navigation follows normal browser focus and scrolling behavior.

## Progressive enhancement and accessibility notes

Start with headings, readable document structure, and useful source-order content. Without JavaScript, readers retain the article, native heading navigation, any author-provided list, and regular fragment links; only generated active context, generated IDs, and the optional status are absent.

With JavaScript, the current rendered item receives `aria-current="location"` by default, visual separators are `aria-hidden`, and `announceChanges: true` appends a visually hidden polite, atomic status. This can provide useful orientation while scrolling but may be too chatty for dense documents; disable it when the surrounding experience already gives equivalent context. The package ignores headings hidden from the accessibility tree unless `includeHiddenHeadings` is explicitly enabled.

`destroy()` restores package-managed state but cannot restore changes another script makes to headings, labels, or the list while the instance is active. Call `refresh()` after framework rendering that adds, removes, hides, renames, or reorders headings. Test the final reading order, heading hierarchy, fragment destinations, sticky overlap, high-zoom layout, and announcements with the browsers and assistive technologies your product supports. Using this helper is not a claim of complete WCAG conformance.

## Known limitations and browser support

- Version 1.0.0 is ESM-only and publishes no explicit browser or assistive-technology support matrix; test the standard DOM and scroll behavior against your supported environment.
- The active item depends on each heading’s viewport position and `activeOffset`; sticky headers, layout shifts, nested scrolling containers, or virtualized content may need an integration-specific offset or explicit `update()`.
- It observes window scroll and resize only. It does not use `IntersectionObserver`, watch DOM mutations, track router navigation, or understand a framework’s render lifecycle.
- The default heading selector excludes `h1`, `h5`, and `h6`; configure it carefully rather than flattening a document’s semantics merely to fit the breadcrumb.
- Generated IDs are document-wide and are based on normalized heading text. Existing duplicate IDs and dynamic document changes remain application concerns.
- `maxItems` collapses parents into a non-interactive ellipsis; it is not an expandable breadcrumb menu.
- Links are optional and the current item is unlinked by default. The plugin does not validate external or callback-produced hrefs.
- The changelog contains an initial 1.0.0 release entry dated 2026-08-10. The package provides no addon exports.
- The npm tarball includes runtime, declarations, docs metadata, CSS, README, changelog, and license, but not the repository’s generated `docs/` directory or its Basic and Lifecycle Events examples. Their public paths are documented by the README and the `./docs` metadata; this page does not depend on those files.
