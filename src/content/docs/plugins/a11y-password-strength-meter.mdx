`a11y-password-strength-meter` progressively enhances an authored password field with local strength scoring, a native progress element, visible requirement states, and polite announcements when the strength label changes. It has no framework, network service, or password-strength dependency.

<Aside type="caution" title="Guidance is not password security">
  The meter provides local UI guidance. It is not backend validation, credential storage, breached-password checking, rate limiting, or a complete security policy. Keep server validation authoritative and review the completed account flow with security and accessibility specialists.
</Aside>

## Use when

- A semantic account form needs explainable password guidance while the user types.
- Users should receive the same requirement state visually and non-visually.
- Password scoring must stay local and avoid external services.
- You want authored fallback instructions before JavaScript initializes.

## Avoid when

- A strength label might be presented as proof that a password is secure.
- Your policy depends on breached-password data or server-owned account context.
- You cannot author a visible label, helper text, feedback paragraph, and stable IDs.
- A passphrase-friendly policy conflicts with the package's five fixed requirement types.

## Required markup

Author useful instructions and feedback in HTML so the field remains understandable before JavaScript loads. The meter root references the password input and feedback paragraph by ID.

```html
<label for="password">Create password</label>
<input
  id="password"
  name="password"
  type="password"
  autocomplete="new-password"
  aria-describedby="password-help password-strength-feedback"
/>
<p id="password-help">Use at least 12 characters with uppercase and lowercase letters, a number, and a symbol.</p>

<div data-a11y-password-strength-meter data-input-id="password" data-feedback-id="password-strength-feedback">
  <p id="password-strength-feedback">Password strength: Not rated</p>
  <ul class="a11y-password-strength-meter__requirements" aria-label="Password requirements">
    <li data-requirement="length" data-length="12" data-met="false">
      <span class="a11y-password-strength-meter__requirement-status">Needed</span>
      <span class="a11y-password-strength-meter__requirement-text">At least 12 characters</span>
    </li>
    <!-- Repeat for uppercase, lowercase, number, and symbol. -->
  </ul>
</div>
```

Supported `data-requirement` values are `length`, `uppercase`, `lowercase`, `number`, and `symbol`. `data-length` on the length item overrides the instance-level minimum for that authored requirement.

## Options and messages

| Option | Attribute | Default or purpose |
| --- | --- | --- |
| `inputId` | `data-input-id` | ID of the password input to observe. |
| `feedbackId` | `data-feedback-id` | Visible feedback ID; defaults to `password-strength-feedback`. |
| `minLength` | `data-min-length` | Minimum length; defaults to `12`. Accepts a number or numeric string. |
| `announce` | `data-announce` | Polite announcements are enabled unless set to `false`. |
| `messages` | localized `data-*` attributes | Override labels, templates, ARIA labels, errors, and requirement text. |

Message attributes include `data-strength-label-fair`, `data-met-text`, `data-needed-text`, `data-strength-template`, `data-requirements-summary-template`, `data-live-template`, `data-progress-label`, `data-progress-value-template`, `data-requirements-label`, `data-input-unconfigured-message`, and `data-input-missing-message`.

For localization, set the document or container `lang`, translate every authored label and instruction, then override package-generated messages through `messages` or the corresponding data attributes.

## API and instance methods

| Export or method | Purpose |
| --- | --- |
| `A11yPasswordStrengthMeter` | Class for one meter root; `getInstance(root)` reads an existing instance. |
| `createPasswordStrengthMeter(root, options?)` | Initialize one root. Duplicate initialization returns its existing instance. |
| `initPasswordStrengthMeters(options?)` | Initialize all meter roots in the document; returns an empty array when `document` is unavailable. |
| `getPasswordStrength(password, options?)` | Return `score`, `maxScore`, `level`, and requirement states using local, explainable checks. |
| `PASSWORD_STRENGTH_LEVELS` | Constants for `not-rated`, `too-weak`, `weak`, `fair`, `strong`, and `very-strong`. |
| `PASSWORD_STRENGTH_METER_EVENTS` | Constants for the three lifecycle event names. |
| `update({ announce?, dispatchChange? }?)` | Recalculate and render from the current observed input. |
| `destroy()` | Remove input listeners, plugin-added descriptions, initialized state, and generated UI state. |

The class also exposes `element`, `root`, and a mutable `messages` property. TypeScript declarations export the option, result, message, requirement, event-detail, and instance types.

## Events

Events bubble from the meter root. Password values are deliberately absent from event detail.

| Event | Detail | When it fires |
| --- | --- | --- |
| `a11y-password-strength-meter:init` | `{ instance }` | Initialization completes. |
| `a11y-password-strength-meter:change` | `{ instance, label, metCount, result }` | An update dispatches a changed result. |
| `a11y-password-strength-meter:destroy` | `{ instance }` | Cleanup completes. |

## Addons and integrations

Version 1.0.0 publishes no addon subpaths. Integrate through the main runtime exports and lifecycle events. A package-maintained registration example composes the meter with [`a11y-form-validator`](/plugins/a11y-form-validator/) so strength guidance and form errors remain separate concerns.

## CSS customization

The public stylesheet uses `.a11y-password-strength-meter` and BEM descendants. Its public custom properties include:

```css
.account-meter {
  --a11y-password-strength-meter-radius: 0.5rem;
  --a11y-password-strength-meter-gap: 0.625rem;
  --a11y-password-strength-meter-muted: #475569;
  --a11y-password-strength-meter-neutral: #64748b;
  --a11y-password-strength-meter-danger: #b42318;
  --a11y-password-strength-meter-warning: #8a4b08;
  --a11y-password-strength-meter-fair: #6b6500;
  --a11y-password-strength-meter-good: #16704a;
  --a11y-password-strength-meter-strong: #075e3b;
  --a11y-password-strength-meter-progress-track: #e2e8f0;
}
```

States are exposed through `data-strength="too-weak|weak|fair|strong|very-strong"`. Preserve the visible requirement words and adequate contrast so color is never the only cue. The package stylesheet includes `prefers-reduced-motion: reduce` safeguards.

## Keyboard and focus behavior

| Key | Behavior |
| --- | --- |
| <kbd>Tab</kbd> / <kbd>Shift</kbd>+<kbd>Tab</kbd> | Move through the native password field and surrounding controls in document order. |
| <kbd>Enter</kbd> | Uses the enclosing form's native submit behavior. |

The generated progress, labels, checklist, and live region are informational and do not add tab stops or a custom keyboard model. Typing does not move focus. The plugin does not move focus during initialization, updates, or destruction; any submit-error focus policy belongs to the form integration.

## Progressive enhancement and accessibility notes

Keep a visible label, authored helper text, requirement list, real form action, and server-side validation. Before JavaScript loads, users still receive the password policy and an unrated feedback state. After initialization, the plugin connects feedback through `aria-describedby`, creates native progress semantics with `aria-valuetext`, updates visible status text, and announces only strength-label changes through a polite live region.

Call `update()` after programmatically changing the password value. Call `destroy()` when removing the form or unmounting its view. Test the completed flow with target browser and assistive-technology combinations; the package does not claim complete WCAG conformance.

## Known limitations and browser support

- The score is local guidance, not backend validation or proof of password security.
- The package does not query breached-password databases or external APIs.
- The five built-in requirement IDs are length, uppercase, lowercase, number, and symbol; product policy still needs independent review.
- The package does not create the password field, label, helper copy, or full requirement list for you.
- Version 1.0.0 does not publish addon exports or an explicit browser-support matrix. Its ESM build and standard DOM APIs target modern browsers; verify your own support policy.
- The published tarball names the maintained examples in docs metadata and README but does not include their HTML files; they remain available in the repository and hosted demo.
